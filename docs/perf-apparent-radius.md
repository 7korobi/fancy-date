# 見かけの半径計算: 性能基準値

見かけの半径を太陽・月の出入り計算へ組み込む前後で、同じ測定条件を比較するための基準値。

## 変更前

- 測定日時: 2026-07-31 03:07 JST
- CPU architecture: `arm64`
- macOS: `15.6`
- Bun: `1.2.16`
- Node.js: `v22.12.0`
- コマンド: `bun run perf:apparent-radius`
- 各ケース: warmup 50回、本測定1000回、5サンプルの中央値
- 対象: `Calendar.GregorianAstronomical`、地点は既存の天文東京、入力は2024-03-20

| ケース                          | 1000回中央値 |  1回平均 |
| ------------------------------- | -----------: | -------: |
| `EarthSolarOrbital.solarEvents` |   131.270 ms | 0.131 ms |
| `EarthMoonOrbital.lunarEvents`  |   369.509 ms | 0.370 ms |
| `GregorianAstronomical.solor`   |   126.238 ms | 0.126 ms |
| `GregorianAstronomical.lunar`   |   361.638 ms | 0.362 ms |

## 実装後

- 測定日時: 2026-07-31 03:15 JST
- 条件: 変更前と同じ。`bun run perf:apparent-radius`

| ケース                          | 1000回中央値 |  1回平均 | 変更前比 |
| ------------------------------- | -----------: | -------: | -------: |
| `EarthSolarOrbital.solarEvents` |   131.135 ms | 0.131 ms |    -0.1% |
| `EarthMoonOrbital.lunarEvents`  |   375.686 ms | 0.376 ms |    +1.7% |
| `GregorianAstronomical.solor`   |   126.510 ms | 0.127 ms |    +0.2% |
| `GregorianAstronomical.lunar`   |   362.302 ms | 0.362 ms |    +0.2% |

追加処理による増加は最大でも約1.7%で、今回の計測条件では過大な負荷にはならない。
月側は既存の `lunarHorizontal()` が計算した距離を角半径計算へ再利用している。

## 精度baselineの更新

角半径変動を反映したため、NAOJ fixtureの記録baselineも更新した。公開fixtureの
許容範囲内だが、旧モデルと同じ数値ではない。

- 太陽イベント: 日没最大差 `0.059分 -> 0.073分`
- 月イベント: 月出最大差 `0.347分 -> 0.442分`

これはそれぞれ太陽距離・月距離による角半径変動を反映した意図的な差分である。

## 比較基準

実装後に同じコマンドを実行し、各ケースの中央値を比較する。追加処理の評価は、
絶対時間と変更前からの増加率の両方で行う。環境差による揺れを考慮し、1回の
測定差だけで回帰と判定せず、同じ環境で複数回測定する。

| 目安                 | 判定                                     |
| -------------------- | ---------------------------------------- |
| 増加率10%未満        | 通常の測定揺れの範囲として扱う           |
| 増加率10%以上30%未満 | 実装の妥当性と呼び出し回数を確認する     |
| 増加率30%以上        | 計算の共有化・事前計算・近似を再検討する |

この基準値は天体イベント計算そのものの比較用であり、創作赤星の真夜中起点の
暦日計算には見かけの出入り計算が現状存在しないため、そこへの性能影響は含めない。
